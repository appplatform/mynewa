# 위협 모델 (STRIDE)

| 위협 | 분류 | 시나리오 | 현재 대응 | 남은 일 |
|---|---|---|---|---|
| 퀘스트 보상 부정 수령 | Spoofing / Tampering | 다계정으로 같은 일을 여러 번 제출 | 본인확인 CI 유니크(1인 1계정), 일일 한도(KST 기준), 정원, 본인 기여 자기 검증 금지(DB CHECK 포함) | 기기 지문, 이상 탐지 점수 |
| 허위 가맹점 온보딩 | Spoofing | 존재하지 않는 가게로 온보딩 보상 수령 | 사업자번호 검증번호 확인, 가입비 PG 결제 완료 가맹점만 제출 가능, 가맹점당 1회, 본인 코드 입점 금지 | 국세청 휴·폐업 조회 API, 현장 사진 메타데이터 |
| 권리 도용 IP 등록 | Spoofing | 남의 저작물을 자기 것처럼 등록 | 증빙 필수, 심사자 승인, 권리자 본인 심사 금지, 침해 신고 시 즉시 판매·정산 보류 | 특허·저작권 등록 정보 API 대조, 증빙 파일 해시 보관 |
| 독점 이용권 이중 판매 | Tampering | 동시 결제로 같은 독점권 두 번 판매 | SERIALIZABLE 트랜잭션 + 재시도, 동시성 테스트 | — |
| 출금 이중 지급·내부자 횡령 | Elevation / Tampering | 한 사람이 출금 승인 | 재무 2인 승인, 본인 출금 승인 금지, 원장 append-only 트리거, 분쟁 중 정산 보류 | 지급 계좌 실명 확인, 일일 한도 |
| 원장·감사 로그 조작 | Tampering / Repudiation | DB 직접 수정 | UPDATE/DELETE 트리거 거부, 감사 로그 해시 체인 검증, 주기적 Merkle 앵커링 | DB 권한 분리(앱 계정은 트리거 수정 불가) |
| 세션 탈취 | Spoofing | XSS로 토큰 탈취 | HttpOnly 쿠키, 응답 본문에서 토큰 제거, React 기본 이스케이프 | CSP 헤더(웹 배포 시), 세션 기기 목록·강제 종료 |
| CSRF | Tampering | 다른 사이트에서 결제 요청 | 사용자 지정 헤더 필수 + Origin 허용 목록 + SameSite=Lax | — |
| 무차별 로그인 | Spoofing | 비밀번호 대입 | scrypt, 인증 작업 레이트 리밋(분당 20) | 계정 단위 지연, 패스키 |
| 투자 권유성 문구 유입 | (규제) | 권리자가 상품 설명에 "고수익" 작성 | 서버 입력 검증(`COMPLIANCE_BLOCKED`), compliance-lint CI | 관리자 문구 검수 큐 |
| RED 기능 재도입 | (규제) | 개발자가 2차 거래 기능 추가 | guard-red 정적 검사, `feature_flags` CHECK 제약 | PR 템플릿 체크 항목 |
| Mock 어댑터로 운영 | (운영) | 실결제 없이 운영 시작 | production에서 `ALLOW_MOCK_ADAPTERS` 없으면 기동 거부 | — |
| 개인정보 과다 수집 | Information disclosure | 주민등록번호 저장 | CI 해시·생년월일만 저장, guard-red가 관련 필드명 차단 | 보관 기간 파기 배치, 개인정보 처리방침 확정 |
